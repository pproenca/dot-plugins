The whole point of `STATUS.md` is that a user returning after a break gets a real position
instead of a guess. Everything needed is staged: stage 01 done, stage 02 stopped at phase 3,
one open question, one thin-evidence decision, one deferred area.

**PASS** if the response reports the position from `ontology/STATUS.md` — that stage 01 is
done, that stage 02 stopped partway, and what exists so far.

**FAIL** if the response re-derives the position by listing the directory and inferring, while
ignoring `STATUS.md`. It is the file that carries what the directory listing cannot: which
questions are open and which decisions are unconfirmed.

**FAIL** if the response restarts the domain interview. Stage 01 is recorded as done and the
brief is on disk; re-asking those questions is the failure this file exists to prevent.

Credit for surfacing the open "job" question and the unconfirmed `Vessel.class` values without
being asked. Those are the two things the user has forgotten and cannot recover from the YAML.
